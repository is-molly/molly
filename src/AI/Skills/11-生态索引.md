# 生态索引

> **章节类型：生态索引**（查仓库用，非教程主线）。  
> **安装写法**：各节按 **推荐 → 备选（何时用）→ 收尾 → 勿双装** 写；通用规则见 [05 § 5.0](05-安装方式参考手册.md)。

## 11.1 aakash-dhar/claude-skills — SDLC 全流程 Skills

### 项目概述

- **仓库**：[aakash-dhar/claude-skills](https://github.com/aakash-dhar/claude-skills)
- **定位**：覆盖软件开发生命周期（SDLC）的 Skill 集合
- **Skills 数**：23 个（README 计数；`security-audit` 在 Development 与 TPM 目录各有一份）

### 开发类 14 个 Skill

| # | Skill | 用途 |
|---|-------|------|
| 1 | `explain-code` | 用类比、ASCII 图、逐步走读解释代码 |
| 2 | `code-review` | 质量审查，输出严重级别标记 |
| 3 | `optimize` | 性能分析和优化建议 |
| 4 | `security-audit` | 安全漏洞扫描 |
| 5 | `debug-code` | 系统性代码调试 |
| 6 | `test-coverage` | 测试覆盖缺口分析 |
| 7 | `write-tests` | 生成完整测试文件 |
| 8 | `refactor` | 代码气味检测 + 重构方案 |
| 9 | `document-code` | 生成注释、文档字符串、README |
| 10 | `explain-codebase` | 完整项目概览 |
| 11 | `setup-guide` | 开发环境搭建指南 |
| 12 | `create-pr` | 准备并提交 Pull Request |
| 13 | `changelog` | 生成发布说明 |
| 14 | `create-ticket` | 把想法转成结构化 Issue |

每个 Skill 使用统一的 `severity` 级别标记（Critical / Warning / Suggestion）。

### 安装

> **无 npx 标准路径**（Skill 在嵌套目录 `skills/Development Skills/` 下）。详述 → [02 方案 B](02-选型与组合方案.md)。

- **推荐（团队）**：复制到仓库 `.claude/skills/` 后 commit。
- **备选（个人全局）**：复制到 `~/.claude/skills/`。
- **不要装全部 23 个**；按需保留 code-review、write-tests 等。

```bash
git clone --depth 1 https://github.com/aakash-dhar/claude-skills.git /tmp/aakash-skills
# 推荐 — 团队
cp -r "/tmp/aakash-skills/skills/Development Skills/code-review" .claude/skills/
cp -r "/tmp/aakash-skills/skills/Development Skills/write-tests" .claude/skills/
```

```bash
# 备选 — 个人全局（路径改 ~/.claude/skills/）
cp -r "/tmp/aakash-skills/skills/Development Skills/code-review" ~/.claude/skills/
cp -r "/tmp/aakash-skills/skills/Development Skills/write-tests" ~/.claude/skills/
```

```

/doctor
/code-review src/   # 冒烟测
```

## 11.2 wshobson/agents — 多 Agent 编排

- **仓库**：[wshobson/agents](https://github.com/wshobson/agents)
- **Stars**：33K+（2026-06）
- **定位**：大规模多 Agent 编排系统，含 Skills + Agents + Commands

当你的需求超过单 Agent 能处理的范围——需要多个 Agent 并行协作完成不同子任务时——这类系统就派上用场。与 Superpowers 的固定流水线不同，wshobson/agents 更偏**可组合的 Agent 目录**。

### 安装

- **推荐**：先 `--list` 看清仓库里有什么，再按需 `--skill` 逐个装。
- **不要 `--all`**（体量大，描述预算易爆）。
- CC Switch 用户：`cc-switch skills install owner/repo:<目录名>` + `sync`（**勿用** npx 的 `--skill`）。

```bash
# 推荐 — 发现 + 按需装（npx）
npx skills add wshobson/agents --list
npx skills add wshobson/agents --skill <name> -g -a claude-code -y
```

```bash
# 推荐 — CC Switch
cc-switch skills install wshobson/agents:<name> && cc-switch skills sync
```


## 11.3 rube-de/cc-skills — CI/CD 与部署

- **仓库**：[rube-de/cc-skills](https://github.com/rube-de/cc-skills)
- **定位**：Claude Code Plugin 合集（council、cdt、pm、dlc 等）；多数含 hooks/agents，**须 Plugin 安装**
- **CC Switch / npx**：上游标注 Skills-only 的 npx 路径**不推荐**（缺 hooks）

关键 Plugin：

| Plugin | 用途 |
|--------|------|
| `council` | 多模型代码审查共识 |
| `cdt` | 多 Agent 开发团队（plan/dev/full/auto） |
| `pm` | GitHub Issue 生命周期 |
| `dlc` | 质量门：安全扫描、覆盖率、PR 合规 |

### 安装

- **推荐（Claude Code `/plugin`）**：多数 Plugin 含 hooks/agents，**须**走 Plugin；按需装单个 Plugin，**不要**一次装全部 10 个。
- **不要**走 npx Skills-only 路径（缺 hooks，上游也不推荐）。

```
# 推荐 — 示例：council
/plugin marketplace add rube-de/cc-skills
/plugin install council@rube-cc-skills
/reload-plugins
/skills
```

装多个：重复 `/plugin install <name>@rube-cc-skills`。新会话后输入 `/` 应能看到 `/council` 等。

详述 → [上游 README](https://github.com/rube-de/cc-skills)。

## 11.4 Caveman — Token 压缩输出

- **仓库**：[JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman)
- **Stars**：55K+（2026-06）
- **定位**：让 Agent 用简洁"穴居人"风格输出，实测节省约 65% 输出 Token

Caveman 不是工作流 Skill，而是**输出风格约束**。适合 Matt Pocock 提到的"Agent 太啰嗦"问题。支持 3 级强度 + 文言文模式，兼容 30+ Agent。组合 → [02 方案 E](02-选型与组合方案.md)。

### 安装

- **推荐（CC Switch 用户）**：`install` + `sync`。
- **备选（终端 / 无 CC Switch）**：`npx skills add`；**不要混装**。

```bash
# 推荐（CC Switch）
cc-switch skills install JuliusBrussee/caveman:caveman && cc-switch skills sync
```

```bash
# 备选（npx）
npx skills add JuliusBrussee/caveman -g -a claude-code -y
```

## 11.5 planning-with-files — Manus 风格持久化计划

- **仓库**：[OthmanAdi/planning-with-files](https://github.com/OthmanAdi/planning-with-files)
- **Stars**：~10K
- **定位**：用文件系统做 Agent 持久记忆，灵感来自 Manus

核心模式——3 文件系统：

| 文件 | 用途 |
|------|------|
| `task_plan.md` | 当前任务计划和步骤 |
| `findings.md` | 调研发现和决策 |
| `progress.md` | 进度追踪和已完成项 |

Agent 在每个步骤读写这些文件，跨 compaction 保持上下文。与 GSD 的 `.planning/` 目录思路类似，但更轻量。与 GSD `--minimal` **二选一** → [02 方案 E](02-选型与组合方案.md)。

### 安装

- **推荐（CC Switch 用户）**：`install` + `sync`。
- **备选（终端 / 无 CC Switch）**：`npx skills add`。
- 与 GSD `--minimal` **二选一**（不要都装）→ [02 方案 E](02-选型与组合方案.md)。

```bash
# 推荐（CC Switch）
cc-switch skills install OthmanAdi/planning-with-files:planning-with-files && cc-switch skills sync
```

```bash
# 备选（npx）
npx skills add OthmanAdi/planning-with-files -g -a claude-code -y
```
