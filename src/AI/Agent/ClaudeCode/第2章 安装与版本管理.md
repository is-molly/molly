# 安装与版本管理

## 安装方式

Claude Code 支持多种安装方式，**官方推荐 Native Install**，因为它会自动在后台更新，始终保持在最新版本。

### Native Install（推荐）

**macOS / Linux / WSL：**

```shell
curl -fsSL https://claude.ai/install.sh | bash
```

**Windows PowerShell：**

```powershell
irm https://claude.ai/install.ps1 | iex
```

**Windows CMD：**

```cmd
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

> **注意**：在 Windows 上区分 PowerShell 和 CMD。如果看到 `The token '&&' is not a valid statement separator`，说明你正在 PowerShell 中，应该用上面的 PowerShell 命令。终端提示符显示 `PS C:\>` 时在 PowerShell，显示 `C:\>` 时在 CMD。

**Windows 额外要求**：需要安装 [Git for Windows](https://git-scm.com/downloads/win)，以便 Claude Code 使用 Bash 工具。如果未安装 Git for Windows，Claude Code 会改用 PowerShell 作为 Shell 工具。WSL 环境不需要 Git for Windows。

Native Install 会在后台**自动更新**，无需手动操作。

### Homebrew（macOS / Linux）

```shell
brew install --cask claude-code
```

Homebrew 提供两个 cask 通道：

| Cask | 说明 |
|------|------|
| `claude-code` | **稳定版**，通常滞后最新版约一周，跳过有重大回归的版本 |
| `claude-code@latest` | **最新版**，发布后立即可用 |

Homebrew 安装**不会自动更新**，需要定期手动执行：

```shell
brew upgrade claude-code
# 或者如果安装的是 latest 通道：
brew upgrade claude-code@latest
```

### WinGet（Windows）

```shell
winget install Anthropic.ClaudeCode
```

同样不会自动更新，定期执行：

```shell
winget upgrade Anthropic.ClaudeCode
```

### npm

```shell
npm install -g @anthropic-ai/claude-code
```

npm 安装也不自动更新，需要 `npm update -g @anthropic-ai/claude-code`。

### Linux 包管理器

支持 Debian（apt）、Fedora/RHEL（dnf）、Alpine（apk）等发行版的包管理器安装。详见 [官方 setup 文档](https://code.claude.com/docs/en/setup#install-with-linux-package-managers)。

### 安装方式对比

| 方式 | 平台 | 自动更新 | 推荐场景 |
|------|------|----------|----------|
| Native Install | 全平台 | 是 | 日常开发，推荐首选 |
| Homebrew | macOS / Linux | 否 | 习惯 Homebrew 管理软件的用户 |
| WinGet | Windows | 否 | Windows 包管理偏好 |
| npm | 全平台 | 否 | 已有 Node.js 环境的用户 |
| apt/dnf/apk | Linux | 否 | 企业批量部署 |

## 启动与验证

安装完成后，在任意项目目录下启动：

```shell
cd your-project
claude
```

首次使用会提示登录。验证安装版本：

```shell
claude --version
# 或
claude -v
```

### 更新到最新版

```shell
claude update
```

如果是通过 Homebrew / WinGet / npm 等包管理器安装的，更新命令会提示使用对应的包管理器语法。

## 认证方式

Claude Code 支持三种认证方式：

### 1. OAuth 登录（默认）

首次运行 `claude` 时，会自动打开浏览器完成 OAuth 认证。需要 [Claude 订阅](https://claude.com/pricing)（Pro / Max / Team / Enterprise）或 [Anthropic Console](https://console.anthropic.com/) 账号。

在无法打开浏览器的环境中（WSL2、SSH、容器），`claude auth login` 支持**直接将 OAuth 验证码粘贴到终端中**完成认证。

### 2. API Key

设置环境变量即可使用 API Key 认证：

```shell
export ANTHROPIC_API_KEY=sk-ant-xxx
```

API Key 用户可以通过 `--betas` 标志启用 Beta 功能。

### 3. 第三方 API 代理

将 `ANTHROPIC_BASE_URL` 指向兼容 Anthropic Messages API 的第三方代理地址：

```shell
export ANTHROPIC_BASE_URL=https://your-proxy.com
```

Claude Code 终端 CLI 和 VS Code 扩展均支持第三方 API 提供方。当 `ANTHROPIC_BASE_URL` 指向一个 Anthropic 兼容的 Gateway 时，`/model` 选择器会自动列出 Gateway 的 `/v1/models` 端点返回的模型。

> **补充工具**：如果你需要频繁在多个 API 配置间切换（例如官方 API、多个第三方代理），社区开源的 [CC Switch](https://github.com/farion1231/cc-switch) 提供了可视化的多配置管理。详见附录 C。

### API Key 动态生成

对于需要动态获取短期凭证的场景，可以在 `settings.json` 中配置 `apiKeyHelper`，指向一个生成 API Key 的脚本，并通过 `CLAUDE_CODE_API_KEY_HELPER_TTL_MS` 设置刷新间隔。

## 版本管理策略

### 发布通道

Claude Code 有两个发布通道，对应 `settings.json` 中的 `autoUpdatesChannel` 配置：

| 通道 | 说明 |
|------|------|
| `latest`（默认） | 最新发布，第一时间获得新功能 |
| `stable` | 稳定版，滞后约一周，跳过有重大回归的版本 |

Native Install 默认使用 `latest` 通道并自动更新。切换到 `stable` 通道：

```shell
# 在 settings.json 中设置，或使用 /config key=value 语法
/config autoUpdatesChannel stable
```

### 禁止自动更新

通过环境变量禁止 Native Install 的自动更新：

```shell
export DISABLE_AUTOUPDATER=1
```

### 版本回退

如果需要回退到指定版本：

```shell
# npm 方式
npm install -g @anthropic-ai/claude-code@2.1.100

# Homebrew 方式可以安装特定版本
brew install --cask claude-code@<version>
```

## 配置目录结构

安装并首次启动后，Claude Code 会创建以下配置目录：

```
~/.claude/
├── settings.json          # 用户级设置（全局生效）
├── CLAUDE.md              # 用户级记忆（全局生效）
├── agents/                # 用户级子代理定义
├── skills/                # 用户级 Skills
├── commands/              # 用户级自定义命令（已合并进 skills）
├── .claude.json           # OAuth 会话、MCP 配置、项目状态等
└── projects/              # 各项目的会话记录和缓存

项目目录/.claude/
├── settings.json          # 项目级设置（团队共享，可提交 git）
├── settings.local.json    # 项目本地设置（不提交 git）
├── CLAUDE.md              # 项目记忆
├── agents/                # 项目级子代理定义
├── skills/                # 项目级 Skills
├── commands/              # 项目级自定义命令
└── .mcp.json              # 项目级 MCP Server 配置
```

## 将 claude 加入 PATH 后可能出现的问题

如果你使用 Native Install 安装，`claude` 命令会自动加入 PATH。如果安装后无法识别 `claude` 命令，检查：

1. **macOS / Linux**：确认 `~/.local/bin` 在 PATH 中，或重新打开终端
2. **Windows**：确认安装目录已加入系统 PATH，或重启 PowerShell / CMD
3. 如果安装过程被安全软件拦截，检查终端是否有权限错误
