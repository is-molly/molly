# 常见场景速查

本章汇总日常使用 Claude Code 的典型场景和推荐的命令/流程组合，作为快速参考。

## 新功能开发

**标准流程：**

```
1. /plan 描述新功能需求（意图 + 约束 + 涉及的模块）
2. 审查 Claude 提出的方案，讨论修改
3. 方案确认后按 Shift+Tab 切换为 acceptEdits 或 auto 模式
4. 或输入 "批准方案，开始实施"
5. Claude 完成后运行 /simplify 审查代码质量
```

**推荐配置：**

```shell
claude --model opusplan --permission-mode plan
```

## Bug 修复

**快速修复：**

```
claude "fix: 登录页面在 Safari 中按钮点击无响应，错误信息：[粘贴错误日志]"
```

**深度诊断：**

```
1. 描述 Bug 现象和复现步骤
2. 让 Claude 追踪代码路径
3. Claude 提出假设 → 验证（加日志/跑测试）→ 确认根因 → 修复
4. 修复后让 Claude 写回归测试
```

**使用 `/debug`：**

```
/debug 启动调试日志
描述问题
Claude 会检查 debug 日志帮助诊断
```

## Code Review

**当前分支审查：**

```
帮我 review 当前分支的所有改动
```

**创建 Code Reviewer Subagent（第 18 章）后：**

```
Use the code-reviewer subagent to review my changes
```

**自动 PR 审查：** 配置 GitHub Actions 后，每次 PR 自动触发 Claude 审查。

## 大型重构 / 迁移

**使用 `/batch`：**

```
/batch migrate src/ from JavaScript to TypeScript
/batch replace class components with functional components
```

**使用多个并行 Worktree：**

```shell
# Terminal 1: 整体 Plan
claude --worktree migration-plan --model opus --permission-mode plan

# Terminal 2-5: 在 Plan 批准后并行执行各模块
claude --worktree module-a
claude --worktree module-b
claude --worktree module-c
```

## 代码库探索

**了解项目结构：**

```
帮我理解这个项目的整体架构和关键模块
```

**追踪功能流程：**

```
从用户点击"下单"按钮开始，追踪整个订单创建的数据流
```

**查找实现：**

```
这个项目中认证逻辑是怎么实现的？找到所有相关文件
```

## 文档编写

```
根据 src/api/ 目录的代码生成 API 文档
帮我写一个 README，介绍这个项目的 setup 步骤
```

## 非编码任务

| 任务类型 | 示例 prompt |
|----------|------------|
| 竞品分析 | 分析这 5 个竞品网站的功能差异，生成对比表 |
| 日志分析 | `tail -200 app.log \| claude -p "找出所有异常并分类"` |
| 数据处理 | 读取 data.csv，分析趋势并生成可视化建议 |
| 研究调研 | 研究这个开源库的社区活跃度、替代方案和迁移成本 |
